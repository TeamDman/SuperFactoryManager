## Purpose and execution order

Make source consolidation a repeatable command-driven loop: compare a real Liquid projection with its pinned Git oracle, identify the next unresolved file, prepare or refine its template, and compare again. The oracle is the exact source state we intend to reconstruct, not an alternative production input.

First complete the sub-second next-file guidance milestone below. Then maintain previous-release text projections for all ten Minecraft versions, oldest to newest. Next complete 1.19.2 `dev-all`, then each remaining version's `dev-all` against its own development branch. Build and compare JARs only after text fidelity passes. Rust compilation needed to develop the CLI is not a Minecraft/JAR build gate.

Targets in order: 1.19.2, 1.19.4, 1.20, 1.20.1, 1.20.2, 1.20.3, 1.20.4, 1.21.0, 1.21.1 and 26.1.2. The existing 1.21.0 catalog key denotes Minecraft 1.21.

The authored root remains `platform/minecraft/core-liquid-template/`. Contexts remain in `platform/minecraft/projections.json`; ordinary generated projects live under `platform/minecraft/projections/<key>/`. Every Java input is templated without a `.liquid` filename suffix. `dev-all` enables the fine-grained feature owners needed to reconstruct that target's captured development state. It does not enable every global flag indiscriminately or require porting 1.19.2-only features to other versions.

The current narrow `sfm-dev` selections are transitional, not complete dev-all contexts. Oracle bindings do not enable features: review and complete each target's feature bundle in the canonical catalog. Missing owner/context configuration is unresolved work, not a passing development row. The required matrix is the ten release and ten dev-all contexts; additional experimental combinations remain supported without silently changing that acceptance denominator.

## Comparison contract

Oracle bindings are recorded in `platform/minecraft/projection-oracles.json`. They bind existing projection keys to full Git refs, peeled commit/tree IDs, source roots and inventory identities. This is comparison metadata; the canonical catalog still controls features and generation. Documented build-layout mappings remain required where authored project layout differs from its oracle.

Resolve refs once through raw local gix reads with isolated configuration and replacement-object interpretation disabled. Do not check out branches, change the index, run hooks, use textconv/filters, fetch objects implicitly or materialize a historical tree for production. Missing refs/objects remain errors. Detect changed branch heads separately; never silently update the oracle or its denominator. Refreshing pins is explicit and reports what changed. Report `snapshot_matches` separately from `reference_current`: zero mismatches against a frozen commit cannot establish latest-branch completion after that branch moves.

Committed branch heads are the default immutable references. Freeze, status and next now report checkout state through `source_checkout_details`. Observation completeness and authored changes remain separate from committed snapshot matching. A comparison exit code of 0 or `done` does not establish a clean checkout. Preserve dirty work untouched; agreed additions require a separately recorded source snapshot. Canonical authoring inventory includes new untracked core inputs, not only committed files.

Scope includes main Java, tests, GameTests, datagen, generated resources, binary assets and project build/wrapper/dependency/lock inputs. Relevant project-root fixtures/scripts must be accounted for. Build outputs, caches, worlds and IDE-local files are not source oracles. Every exclusion or path-layout mapping is explicit and visible; do not invent a broad exclusion to reduce mismatches.

Compare the fresh in-memory result of the production selector/renderer, not stale files under a projection directory. Separately report manifested-output freshness and contributor-edit conflicts. Exact bytes remain the authority, with raw identities retained. The explicit binding policy permits declared banners, CRLF normalization, one final LF/CRLF difference and the narrow `settings.gradle` project-identity layout allowance. Final-newline allowance applies only to recognized UTF-8 text, never extra blank lines or binary files. Git executable modes are recorded where relevant; unsupported modes, unsafe/nonrepresentable paths and Windows case collisions are explicit errors.

Reports count path/context cells and unique unresolved authored files separately. Show expected, matched, missing, changed, unexpected and error counts. A path that is absent from an oracle is not equivalent to an empty file. `done` requires complete required-context coverage, no mismatches and no unresolved errors. Comparison success is text fidelity, not compilation or gameplay proof.

Template/configuration failures, unknown features, invalid prerequisites, unavailable objects and unreadable inputs must not become ignored files or successful empty inventories. Comparison report exit codes are 0 for matching requested contexts, 1 for valid differences and 2 for invalid/incomplete comparisons. A filtered status can pass while `complete_coverage` and `done` remain false. `next` requires the whole matrix. Discovery and mutation commands report their operation explicitly.

Queue order follows release contexts oldest to newest, dev-all 1.19.2, then remaining dev-all contexts oldest to newest. Within a context, return prerequisite/configuration blockers first, then missing/changed/extra paths in a documented deterministic order. A next-file result identifies its core input, mismatch reason, current/pinned bytes or blob IDs, relevant contexts, known feature owners and recommended command. An extra output is a rule/template review task, not an instruction to delete it automatically.

Cache immutable blobs by object ID. Reuse rendered results only with complete content/context/renderer identity; mtime alone is insufficient. A change can introduce regressions elsewhere, so burndown is measured, not promised to decrease monotonically. Do not treat an old report as current acceptance.

## Command surface

Six commands are integrated through existing `source` parsing and Facet output. Use `--repo-root` when invoking outside the implementation root. The default binary rebuild and strict all-feature Clippy passed after draft integration; the full validation gate remains pending.

| Command | State | Outcome | Writes |
| --- | --- | --- | --- |
| `source oracle freeze` | Integrated | Preview all release and development pins. | Explicit `--apply`; replacing pins also requires `--refresh`. |
| `source oracle status` | Integrated | Compare fresh output; report moved refs, managed-output freshness, scoped extras and checkout observations separately. | None. |
| `source oracle next` | Integrated | Return the first unresolved item in required context order. Checkout and manifested-output inspections are explicitly unobserved; use full status for those audits. | Verified comparison cache only; cold initialization requires `--rebuild-index`. |
| `source oracle diff --projection <key> --file <path>` | Integrated | Compare one rendered/oracle path with bounded native diff. | None. |
| `source oracle seed-missing --projection <key> --file <path>` | Integrated | Preview absent input and witnessed membership across all required contexts. | Create-only `--apply` also requires the preview's `--reviewed-plan` identity. |
| `source oracle draft --file <path> --output-dir <new-directory>` | Integrated | Stage pinned witnesses and ownership review; `--review` validates a reviewed candidate through the production selector/renderer. | New explicit staging directory only; canonical Minecraft inputs and actual linked/shared Git-state directories are forbidden. |

The implemented reports supply the command-driven loop. Validate these surfaces against live required contexts before claiming matrix completion. Reuse report data for later HTML generation.
