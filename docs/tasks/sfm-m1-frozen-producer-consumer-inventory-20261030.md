## Physical savings decision

The dated four-root baseline is **191,151,836,624 NTFS allocated bytes**, including a **133,395,183,096-byte** projection-local `build/sfm-toolchain` cohort. These are nested, not additive. The 23 historical held-input test fixtures occupy **7,883,881,168** allocated bytes; the 33 dev 1.19.2 MCP children occupy **2,777,997,016**, with the nine-root **246,804,480-byte** subset nested inside those 33. The held-fixture and MCP cohorts are distinct. No byte from either has been retired. Present-code nonrecurrence measurements avoided **43,544,576 bytes per eligible new dev 1.19.2 project** and **122,703,944 bytes per comparable successful new NeoForm 1.20.4 invocation**; those are future avoidance, not old-plus-new reclamation.

G1 cannot honestly set a global substantial physical-reduction target from these numbers yet. The specific missing decision is whether historical absolute-path resumability and retained diagnostic payloads for the exact fixture and MCP roots may be surrendered after preserving receipts and proving pinned current-workflow reconstruction. Before an exact retirement request, M6 also needs complete owner union, current readers/publishers, a current allocated baseline and a reviewed candidate list. A conditional sum of these cohorts would be a *scenario*, not approved recoverable savings or a defensible target. The larger mixed 133.4 GB cohort needs further homogeneous ownership classification; it cannot be declared disposable from a directory name. This inventory closes the **74/74 classification deliverable**, while M1.1/G1 numerical acceptance, missing ordered producer/consumer execution joins, M4 required runtime proof and M6 reclamation remain open.
