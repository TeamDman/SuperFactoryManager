## Optional worktree sharing and pruning boundaries

The proposed logical path remains `<checkout>/sfm-toolchain-data/` for **every** worktree. An isolated worktree has a real directory there. An explicitly approved sharing worktree may instead place one directory link **at that root only**, pointing to a common physical cache outside the projection trees. Rust and generated Gradle resolve the same project-relative literal; neither discovers a Git root dynamically or requires a new preferred-directory indirection. Existing persistent/argument overrides are a compatibility and explicit-selection gate at G3, not a silent way to choose sharing. No link or target exists by implication from this plan. A directory link is not a license to follow links below the root, move projection snapshots, or mix mutable world/session files.

On Windows, `mklink /d` creates a directory symbolic link and `mklink /j` creates a junction; junctions can target another **local** volume but not a mapped network volume. The choice is a G7 platform/permission/relocation decision: a relative directory symlink may make a nearby target portable, while a junction is appropriate only for a verified local target and may bind its location. Neither is created automatically, and no OS privilege or security setting change is part of this plan. [Microsoft mklink](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/mklink); [Microsoft junction semantics](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions).

Record both the checkout's **logical alias** and the resolved **physical target** (canonical path, file identity/volume and ownership marker) at selection, publication, accounting and cleanup. The target must be independently owned and durable, not under a worktree's disposable build or a directory that worktree cleanup could remove. Two aliases to one target count as **one** allocation, including during old/new migration peak accounting. Shared artifact locks/read holds and atomic publication must be under the physical target and keyed by the same complete relevant-input recipe across worktrees; incompatible schema/tool recipes occupy different namespaces and never overwrite. Hold or revalidate the admitted physical directory identity across publication/reader lifetimes, failing closed if an alias is switched after preflight. Full source/lock validation remains per checkout. A resource newly required by another worktree is additive. Project compilation, snapshots, worlds, options, session state and diagnostic ownership remain checkout/instance-local. Existing `native_cache_root.rs` and `paths/cache.rs` reparse refusals mean this is a planned narrow change, **not currently working behavior**.

For pruning, an exact current-checkout expected set can start with portable frozen lock paths, authenticated version-manifest downloads and verified asset-index/object references. A derived stage may be expected exactly only when its complete recipe inputs and schema are known from the planner or a validated receipt; lazy runtime inputs, optional profiles, missing/offline owners and old schema entries are conservative/unknown. Define `existing physical entries − expected by this checkout` as **report-only candidates**. It does **not** prove global orphanhood. `git worktree list` is a useful local input but cannot establish ownership of other clones, offline worktrees or preserved rollback artifacts. A shared target's deletion decision would require a complete, explicit owner inventory (including unavailable/retired owners and retained receipts), expected-set union, exclusion of active readers/publishers, a common maintenance lock or equivalent quiescence protocol, last-moment identity/receipt recheck and a separate exact-list approval. If that evidence is incomplete, retain the entry; do not add a persistent owner registry merely for convenience. Any future deletion operates on individually verified physical entries under the canonical target, never a recursive traversal through a checkout symlink/junction.

## Mandatory source-stable validation window

**Integration coordinator:** the active SFM task owner holds the validation lane, assigns one writer per file and maintains the checkpoint/receipt ledger. Parallel research and review may continue read-only. A worker saying “ready” means its own edits are saved, coherent and its generators/test helpers have stopped; it does **not** claim a successful build. The coordinator may run an initial stable baseline build if compiling readiness is unknown. Cargo's target-directory output lock, per-key artifact locks and reader holds protect their own artifacts, **not** this source closure.

For **every** Cargo `check`, `test`, `build` or `run`, and each native source/Gradle/GameTest acceptance command, use **EDIT → QUIESCE → FROZEN VALIDATE → RELEASE**:

1. **EDIT:** assign exact files and generated-output ownership. Integrate coherent worker checkpoints in dependency order: shared API/schema/manifest/lock/build-script changes first, then consumers and generated inputs, then validation. No agent other than the coordinator stages or commits. Review scoped diffs, the index and untracked relevant inputs; never use blanket staging or reset another owner's edits. A failed worker leaves its edits visible and marked incomplete, not silently reverted.
2. **QUIESCE:** stop all source, formatter, codegen, IDE auto-save and fixture/config writers in the command's input closure. Confirm prior child compilers, JVMs, test servers and helpers exited; timeout, cancellation or coordinator failure does not implicitly release a lease. Record exact command, working directory, tool/binary hash, JDK, environment variables that affect inputs, persisted cache/config root and frozen dependency preconditions. Enumerate the actual read closure: Rust crate/path dependencies/proc macros, `build.rs`, `include_bytes!`/templates, `Cargo.toml`/`Cargo.lock`/`.cargo` config; for native/Gradle add catalog/features, authored/generated lock/source/resources, Gradle scripts/wrapper, mappings and selected artifact digests. A generated input must be complete and quiescent before its consumer; a generator itself gets its own writer lease and validation phase. Record HEAD plus path/byte-hash inventory of relevant staged, unstaged and untracked content, not just `git status`.
3. **FROZEN VALIDATE:** coordinator holds an exclusive **source-input writer exclusion** for that closure through result collection. No worker, user-facing helper, formatter, generator or concurrent CLI may edit it. Give mutable effects a separate lease: tests/commands that write the same fixture, cache entry, generated project, persisted configuration, installed CLI or runtime output serialize unless isolation is proven. `cargo test` may run tests concurrently inside one process, so shared fixture/cache writers must be isolated or run serially. Declared output paths may be written by the owner command, but never mistaken for frozen inputs. One heavy desktop command at a time remains the resource rule, separate from source stability.
4. **RELEASE:** wait for every owned process/child and relevant file handle to exit, collect exit/selected-test counts/logs and output artifact identities, then rehash/recheck the frozen input closure and configuration. Matching before/after hashes supplement, but do not replace, writer exclusion (edit-and-revert is possible). If identity drifted or an unowned writer appeared, mark the result **stale**, preserve the evidence, quiesce again and revalidate; do not overwrite a concurrent user edit. Only then thaw and allow queued edits. Attribute a receipt to a later scoped commit only if its relevant source/lock/config byte identity still matches the tested checkpoint; record any post-test change requiring rerun.

**Failure and rollback:** if a worker or coordinator fails, preserve dirty files, staged/index state, cache receipts and diagnostics; identify owned process trees before stopping them and confirm termination before thaw. Do not call `git reset --hard`, broad clean or recursive cache deletion. Repair or reverse only identified own hunks after diff review, leaving user edits intact. Interrupted/partial tests are unvalidated. Recovery resumes at QUIESCE with an explicit new input identity. Global `cache root set/unset`, `install.ps1`, source generation and runtime session changes are serialized writes with their own receipts; an installed binary is never assumed to match the current source build.
