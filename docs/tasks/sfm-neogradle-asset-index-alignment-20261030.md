## Historical migration proposal (subsequently approved and implemented)

Prefer one reviewed **exact-snapshot alignment** for the six NeoGradle targets over growing a permanent metadata bridge. Keep plain 4.34.0/4.35.0 historical locks and manifests byte-for-byte. The exact core key set is `sfm-4.34.0-extended/mc-V`, `sfm-4.35.0-extended/mc-V`, and `sfm-dev/mc-V` for each of the six V values in the table (18 keys). The locked-dependency feature also feeds `sfm-4.34.0-issue610-portable/mc-V` and `sfm-4.35.0-issue610-portable/mc-V` for all six V, plus `sfm-4.34.0-issue610-visual/mc-1.21.1`, `sfm-4.35.0-issue610-visual/mc-1.21.1`, `sfm-4.34.0-issue610/mc-1.21.1`, and `sfm-4.35.0-issue610/mc-1.21.1` (16 additional keys). Thus seven feature-lock inputs feed 34 generated projection locks, not just the 18 core keys. Before a lock change:

1. Pin an exact authenticated v1 launcher snapshot or replace discovery with six explicit content-addressed version URLs. Do not let a moving global manifest select a different URL after review. Record the official URL, full digest, selected timestamp and exact mapping to the six payloads. The four fetched index JSONs and the six authenticated retained version JSONs are proposal evidence, not yet admitted SFM lock inputs.
2. Change `build/lockfiles/V/schema-4.json` for each of the six V targets, plus `build/lockfiles/1.21.0/schema-4-dev-catalog-source.json` for the developer-only catalog source route: each direct version URL and BLAKE3-20 hash becomes the table's v1 payload, with its nested asset-index URL/SHA-1/size and object hashes verified. The 1.21.0 dev-specific lock currently has the same old direct version pin but different source-provider content; retain that difference. These seven inputs feed 18 core extended/dev projections and 16 issue-610 variants; changing only dev would require a new selector or recipe split. `project-inputs.json` selects `schema-2.json` when `locked_dependency_projection` is absent, so plain 4.34.0/4.35.0 release outputs can remain byte-identical if their generation checks pass. Preserve old pins and receipts as historical evidence. The currently pinned v2 manifest does not select these v1 URLs, so changing only direct artifact records would make future regeneration disagree; a reviewed source-discovery recipe transition is required.
3. Design a version/recipe-keyed index cache path and compatible version-metadata path. The current named paths (`assets/indexes/{id}.json`, `versions/{mc}/version.json`) already contain old checked bytes; `acquire_named_frozen_download` verifies existing bytes and fails on mismatch. Do not overwrite them or erase existing receipts to force the new pins. Recheck source-index, compile, launch and runtime receipts whose version-parent or asset-index identities change; preserve all old worlds/options and plain-release fidelity.
4. Separately close cold Gradle resolution. Its own module metadata is unavailable in a fresh `--offline` home, while online NeoGradle refreshes the mutable global manifest. Choose a checked bootstrap/reader contract for the pinned snapshot, and prove fresh-home `help`/JAR plus repeat reuse without arbitrary network substitution. Native lock alignment alone does not close this gate.

Expected benefit was consistent version/asset selection across SFM native and NeoGradle's selected snapshot, with content-addressed asset reuse across projections. The approved migration and its actual coverage are recorded below. Old-cache retirement and plain-release rewrite remain outside this approval.
