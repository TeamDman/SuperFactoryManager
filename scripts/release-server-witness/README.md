This test-only runner compares unchanged official and checked-in projected SFM 4.34.0 JARs. It supports 1.19.2 on Forge 43.4.0, 1.19.4 on Forge 45.0.9, 1.20 on Forge 46.0.10, 1.20.1 on the transitional `net.neoforged:forge:1.20.1-47.1.65` artifact, 1.20.2 on `net.neoforged:neoforge:20.2.86`, 1.20.3 on `net.neoforged:neoforge:20.3.8-beta`, 1.20.4 on `net.neoforged:neoforge:20.4.231` (all with JBRSDK 17.0.14), 1.21.0/1.21.1 on `net.neoforged:neoforge:21.0.143`/`21.1.206` with JBRSDK 21.0.11, and 26.1.2 on `net.neoforged:neoforge:26.1.2.72` with JBRSDK 25.0.3. The same auxiliary probe JAR is loaded in every boot for a target. Minecraft 1.19.2 instead uses a legacy creative-tab array, which is outside its registry-ID snapshot. Client-only text-editor registries are outside this dedicated-server witness.

The driver starts four isolated production servers in order: official seed; official control and projected candidate from byte-identical complete seed-world copies; and official reverse from the candidate-saved world. It requires `Done`, exact loader/Minecraft identity, a sorted registry snapshot, successful save and exit zero in every boot. Control, candidate, and reverse must agree case-sensitively on disk program, derived disk name, legacy label, empty errors, empty warnings, and stone/north/`STRETCH` facade. It compares registry IDs as strings, not runtime numeric ordinals. A missing snapshot, missing selected value, or missing required registry family fails closed.

The scratch root retains per-boot `commands.txt`, `logs/latest.log`, `registry-snapshot.json`, process logs, worlds, and a path-free `result.json`. The default result binds input, runner, probe-source and probe-JAR hashes and includes the exact six observations and registry-ID diff. Do not commit scratch files or absolute machine paths. A disk-space error is a terminal stop: do not clean, delete, or retry until the user resolves it. A passing default result is only a selected server registry/save witness, not general save, gameplay, client, or release acceptance.

## Opt-in 1.21.0 vanilla-barrel transfer

Use `-Target 1.21.0 -Mode vanilla-barrel-transfer` with the same exact 21.0.143 installer, joined NeoForm JAR, JBRSDK 21.0.11 and unchanged SFM JARs listed above. The default mode remains `registry-save` and keeps its six-value fixture and report. The transfer mode requires a new absent scratch root and writes a separate `sfm:release_server_transfer_witness@1` report.

The official seed has an empty manager disk slot, one vanilla barrel with 64 dirt, and another empty vanilla barrel. Both barrels sit next to the manager and both adjacent chunks are force-loaded. The runner asserts the source64/destination-empty/inactive-disk state in the seed and both byte-identical clones. It activates the same component-backed program and absolute labels only after each clone passes that check. The official control must move all 64 dirt before the projected candidate runs. An official reverse boot then loads the candidate-saved world without reactivating the disk and checks the persisted barrels and disk fields. Each boot also records a registry snapshot. This covers one item-transfer path, not arbitrary inventory or client behavior.
