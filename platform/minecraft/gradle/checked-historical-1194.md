# Checked historical Gradle route: SFM 4.35.0, Minecraft 1.19.4

From any working directory, run `platform/minecraft/gradle/run-checked-historical-1194.ps1 -Task jar` using the path in this checkout. The script selects the existing plain 4.35.0/1.19.4 projection, runs its Gradle wrapper offline, and loads the repository-owned checked module route. `-Task help` and `-Task compileJava` are also available. `-RerunTasks` requests actual task execution when a warm Gradle output would otherwise be up to date. Gradle requires Java 17 through `JAVA_HOME`; Rust is not needed.

The generated historical build files and schema-2 lock stay byte-identical. The init script derives the checkout root from the fixed projection location, checks the lock, canonical native-root ownership marker including its exact logical repository path, historical version snapshot, tracked Gradle bootstrap supplement, and every declared JAR/POM against `checked-historical-1194-inputs.json` before resolution. It exposes the eight publisher POM modules with `mavenPom()` metadata and only their exact versions. The fifteen direct Maven coordinates include the annotation JAR already pinned by the tracked supplement. Thirty Minecraft library coordinates include seven LWJGL modules; their 28 base/Windows-classifier files are individually joined to the locked snapshot's paths, URLs, sizes and SHA-1 values. Exclusive content prevents matching coordinates from silently resolving through another repository. When `compileJava` enters the task graph, the route also checks the actual resolved classpath bytes for those 28 LWJGL files and the annotation JAR. Missing or changed manifest-listed payloads, metadata, classpath files, or a cache marker from another root fail before build tasks.

Run `platform/minecraft/gradle/test-checked-historical-1194.ps1` with Java 17 to exercise a positive isolated cache fixture, changed historical version snapshot, changed native JAR, changed annotation JAR, changed published JAR, missing publisher POM, missing child module JAR, marker from another cache root, and wrong projection. The nine-case test copies checked inputs to unique task-owned temporary scratch, restores no real cache files, and removes its successful fixture. On failure it leaves the small output logs in the reported temporary location for diagnosis.

This is an exact recipe for one historical projection, not an automatic route for other versions. The cache must already contain the checked files. A fresh machine must separately acquire and verify those exact pins and provision the historical Gradle 7.5 wrapper distribution and Java 17; `--offline` does not install them. The published JEI main JAR remains the Rust direct dependency. Gradle follows its eight-module publisher graph, including six same-version JEI children. Those children introduce no class/resource entry names absent from the aggregate main JAR, but most matching class payloads differ. For one representative `DrawableAnimated` class, the member descriptors and normalized `javap` instruction view match while constant-pool ordering differs. This narrow comparison does not prove that all differing classes are semantically interchangeable; the two resolver contracts keep their respective exact authenticated bytes.

The successful offline compile is currently **partial closure evidence**. A task-owned trace of `compileJava.classpath` has 112 ordered entries: 37 originally checked shared files, 23 exact JARs from this selected lock, 21 additional exact libraries from its pinned Minecraft version metadata, six exact JARs pinned by other selected SFM locks, 21 LWJGL Windows native classifier JARs, `org.jetbrains:annotations:23.0.0`, and three Forge/Minecraft derived JARs without producer-bound receipts in this route. The newly checked route covers the 28 LWJGL base/native classpath JARs and annotation JAR, including actual task classpath bytes. ForgeGradle's generated Minecraft client POM declares the 21 natives with compile scope. The three derived outputs and immutable plugin/tool recipe remain unsealed. The native archives contain no ordinary classes beyond `module-info.class`, but Gradle still supplies them as compiler task inputs. The graph, classpath and corrected metadata joins are in task evidence m450–m458; the expanded route was exercised with nine focused fixtures and a positive dry-run compile graph. This route remains usable with the existing warm cache; it does **not** yet qualify as a strict frozen-lock or fully authenticated compile closure, nor as a fresh-machine bootstrap. Do not use a successful `jar` exit or the checked manifest alone to credit those gates.
